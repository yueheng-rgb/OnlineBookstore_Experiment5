# 项目进度管理计划

## 实验信息
- **实验名称**：实验五——软件项目开发阶段管理
- **项目主题**：在线书店系统开发
- **开发模式**：Scrum 敏捷开发
- **迭代周期**：2 周一个 Sprint

## 团队角色分工

| 角色 | 姓名（占位） | 职责 |
|------|------------|------|
| 产品经理 (PO) | 【填写姓名】 | 需求定义、Backlog 优先级排序、验收标准确认 |
| Scrum Master | 【填写姓名】 | Sprint 计划、每日站会、障碍移除、进度跟踪 |
| 开发人员 1 | 【填写姓名】 | 用户模块 + 图书模块开发 |
| 开发人员 2 | 【填写姓名】 | 购物车模块 + 订单模块开发 |
| 测试人员 | 【填写姓名】 | 单元测试、集成测试、JMeter 压力测试 |

## Sprint 计划

### Sprint 1：基础架构与用户模块（第 1-2 周）
- [x] 项目脚手架搭建（Maven + Spring Boot）
- [x] 数据库设计与实体创建
- [x] 用户注册/登录功能
- [x] 用户 CRUD API
- [x] 单元测试覆盖

### Sprint 2：图书管理与购物车（第 3-4 周）
- [x] 图书 CRUD API
- [x] 图书搜索与分类筛选
- [x] 购物车功能
- [x] 单元测试覆盖

### Sprint 3：订单管理与集成测试（第 5-6 周）
- [x] 订单创建与状态管理
- [x] 库存扣减与恢复
- [x] 集成测试
- [x] JMeter 压力测试准备

### Sprint 4：CI/CD 与交付（第 7-8 周）
- [x] Jenkins Pipeline 配置
- [x] Docker Compose 部署配置
- [x] 文档完善
- [x] 最终交付

## 进度跟踪方式
- 使用 Jira 看板管理任务状态（To Do → In Progress → Done）
- 每日站会更新进度
- Sprint 结束后进行 Review 和 Retrospective

## 风险管理

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 团队对 Spring Boot 3.x 不熟悉 | 高 | 中 | 提前学习官方文档 |
| H2 与 MySQL 行为差异 | 中 | 低 | 使用标准 SQL，避免方言特性 |
| 时间不足 | 高 | 中 | 优先完成核心功能，非核心降级 |
